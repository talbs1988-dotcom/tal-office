# היסודות: כל סקיל של המשרד קורא את זה קודם

## התבניות

התבניות של הפלאגין נמצאות ב-`<Base directory של הסקיל>/../../templates/`.
קוראים אותן עם Read, וכותבים את הקבצים של המשתתף עם Write. **לא מריצים פקודות טרמינל כדי ליצור קבצים או תיקיות** (לא mkdir, לא cp). Write יוצר את התיקייה לבד. ככה הכול עובד אותו דבר במק ובווינדוס, ב-VS Code, באפליקציה ובטרמינל.

## למצוא את המשרד

משרד הוא תיקייה שיש בה `CLAUDE.md` שהשורה הראשונה שלו היא `<!-- tal-office:business -->`.

1. בודקים בתיקייה שבה השיחה נפתחה (תיקיית העבודה הנוכחית).
2. לא נמצא → בודקים בתיקיות שמעליה, אחת אחרי השנייה.
   - נמצא מעל → המשתתף פתח את קלוד בתוך תיקייה פנימית של המשרד. אומרים: "פתחנו את קלוד בתוך תיקייה פנימית. כדי שקלוד יכיר את העסק, עובדים תמיד מהתיקייה הראשית." נותנים את הודעת "פותחים מחדש" עם הנתיב של המשרד, ועוצרים.
3. לא נמצא גם מעל → בודקים בתיקיות שמתחת, רמה אחת בלבד.
   - נמצא אחד → "מצאתי את המשרד ב-<הנתיב>." הודעת "פותחים מחדש" עם הנתיב, ועוצרים.
   - נמצאו כמה → מציגים את הרשימה ושואלים באיזה עובדים. אחרי התשובה, הודעת "פותחים מחדש".
4. לא נמצא בכלל → "עוד אין משרד. מקלידים `/office-start` ונקים אותו." ועוצרים. (חוץ מ-`/office-start` עצמו, שבונה אותו.)

## הודעת "פותחים מחדש"

כותבים בדיוק כך, עם הנתיב המלא:

> **עכשיו פותחים את קלוד בתוך תיקיית המשרד:** `<נתיב מלא>`
>
> **ב-VS Code:** תפריט File ← Open Folder ← בוחרים את התיקייה ← פותחים את Claude Code מהסימן שלו בצד. אם VS Code שואל אם סומכים על התיקייה: "Yes, I trust the authors".
>
> **באפליקציה של Claude:** פותחים שיחה חדשה, ומתחת לתיבת ההודעה בוחרים את התיקייה (Open folder).
>
> **בטרמינל:** במק `cd '<נתיב מלא>' && claude` · בווינדוס `cd '<נתיב מלא>'; claude`
>
> אחרי שנפתח, מקלידים `/office` וממשיכים משם.

## שיחה חדשה

חלק מהדברים נטענים רק כשנפתחת שיחה: ה-`CLAUDE.md`, הזיכרון, ההגדרות, וסקיל או סוכן חדשים. כשצריך, אומרים:

> **פותחים שיחה חדשה באותה תיקייה.** ב-VS Code: הכפתור + (New Conversation) בחלון של Claude Code. באפליקציה: שיחה חדשה, ומוודאים שנבחרה אותה תיקייה. בטרמינל: סוגרים (`/exit`) ומקלידים `claude` שוב.

## איך פונים למשתתף

לפי השורה `- פנייה לבעל העסק:` ב-CLAUDE.md של המשרד (זכר, נקבה או רבים). לא מולאה או שאין עדיין משרד → ברבים.

## קצב העבודה בכל שלב

- **קודם קוראים, אחר כך שואלים.** תשובה שכבר כתובה ב-CLAUDE.md, בזיכרון או ב-`systems/` לא שואלים שוב. אומרים במשפט מה ידוע וממשיכים.
- **שאלה אחת בכל הודעה**, עם דוגמה קצרה לתשובה טובה.
- **שפה פשוטה.** סקיל = מתכון. סוכן = עובד. נוהל = איך עושים את זה אצלנו. מונח טכני שאין ברירה, מסבירים במילים של בעל עסק.
- **מראים את התוצאה**, לא רק מתארים אותה, ושואלים: "מאשרים, או משנים משהו?" לא ממשיכים בלי אישור.
- **"נראה עובד" זה לא "עובד".** אחרי שכותבים קובץ, קוראים אותו שוב ובודקים שהוא באמת שם ושהתוכן נכון. מספרים מה בדקנו.
- **לא דורסים.** קובץ שכבר קיים לא כותבים מחדש. מוסיפים או מעדכנים רק את החלק הרלוונטי, ואומרים מה השתנה.
- בסוף כל שלב: משפט אחד על מה נבנה, והפקודה של השלב הבא.
