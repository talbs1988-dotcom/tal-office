# שלב 1: הקמת המשרד

קודם קוראים את היסודות ועובדים לפיהם: `<Base directory של הסקיל הזה>/../../references/basics.md`.

## א. איפה אנחנו

התיקייה הנוכחית היא התיקייה שבה השיחה נפתחה. בודקים לפי הסדר:

1. **יש בה `CLAUDE.md` שמתחיל ב-`<!-- tal-office:business -->`** → המשרד כבר קיים. בודקים אילו מהקבצים שבסעיף ג חסרים, יוצרים רק אותם, ולא נוגעים במה שקיים. אם לא חסר כלום: "המשרד כבר מוכן. מקלידים `/office` ונמשיך משם." ועוצרים.
2. **המשרד נמצא בתיקייה שמעליה** → כמו ב"למצוא את המשרד" ביסודות: הודעת "פותחים מחדש" עם הנתיב של המשרד, ועוצרים. לא בונים משרד בתוך משרד.
3. **זו תיקייה כללית**: תיקיית הבית, שולחן העבודה, מסמכים, הורדות, או השורש של הדיסק. או שיש בה הרבה קבצים שלא קשורים לעסק → לא בונים כאן. אומרים:

   > כדי שהמשרד יהיה מסודר, הוא צריך תיקייה משלו. ככה יוצרים אותה:
   >
   > 1. **ב-VS Code:** File ← Open Folder. בחלון שנפתח נכנסים לתיקיית הבית (במק: לוחצים Cmd+Shift+H בחלון שנפתח, בווינדוס: `C:\Users\<השם שלכם>`), לוחצים "New Folder", ונותנים לה שם קצר באנגלית בלי רווחים, למשל `dana-studio`. בוחרים אותה ולוחצים Open. אם VS Code שואל אם סומכים על התיקייה, לוחצים "Yes, I trust the authors". זו תיקייה שיצרתם בעצמכם.
   > 2. **באפליקציה של Claude:** יוצרים את התיקייה ב-Finder (במק) או בסייר הקבצים (בווינדוס), בתוך תיקיית הבית. אחר כך בשיחה חדשה, מתחת לתיבת ההודעה, בוחרים אותה (Open folder).
   >
   > אחרי שהתיקייה פתוחה, מקלידים שוב `/office-start`.

   ועוצרים.

4. **הנתיב עובר דרך תיקייה שמסתנכרנת לענן** (יש בו `iCloud`, `Mobile Documents`, `OneDrive`, `Dropbox`, `Google Drive` או `CloudStorage`, או שהוא בתוך שולחן העבודה או המסמכים: `Desktop` או `Documents`, כי במק ובווינדוס הם מסתנכרנים לפעמים לענן) → אומרים במשפט: "התיקייה הזו מסתנכרנת לענן. זה עלול להעלות את הכספת למפתחות ולהאט את העבודה. מומלץ לבנות את המשרד בתיקיית הבית." ושואלים אם להמשיך כאן בכל זאת, או לעבור (ואז ההוראות מסעיף 3).
5. **יש בה כבר `CLAUDE.md` בלי השורה של המשרד** (למשל תיקייה ראשית של עסק שכבר קיימת) → אומרים: "יש כאן כבר קובץ כללים של העסק. אשאיר את כל מה שכתוב בו, ואוסיף מתחת את החלקים של המשרד." ממשיכים רק אחרי אישור. בסעיף ג, במקום לכתוב קובץ חדש: מוסיפים את השורה `<!-- tal-office:business -->` בראש הקובץ, ואת כל הסעיפים של התבנית מתחת לתוכן הקיים. סעיף שכבר קיים בקובץ (למשל "העסק") לא מכפילים: ממלאים ממנו.
6. **אחרת** (תיקייה ריקה, או כמעט ריקה) → ממשיכים ל-ב.

## ב. שתי שאלות, כל אחת בהודעה נפרדת

1. **שם העסק.** אם הגיע כארגומנט, או כתוב כבר ב-CLAUDE.md קיים, לא שואלים. אחרת: "איך קוראים לעסק? כמו שהוא מופיע אצל הלקוחות." (דוגמה: "סטודיו נשימה")
2. **איך לפנות.** "איך לפנות אליכם: בלשון זכר, נקבה או רבים?"

**לפני ההגדרות, משפט אחד ואישור:**

> אני מגדיר גם שני דברים של אבטחה ונוחות: קלוד יוכל לשמור קבצים בתוך תיקיית המשרד בלי לשאול כל פעם (שליחה, מחיקה ופקודות אחרות עדיין יחכו לאישור שלכם), וקלוד לא יוכל לקרוא את הכספת עם המפתחות. מאשרים?

- מאשרים → כותבים את ההגדרות.
- לא מאשרים → כותבים רק את שורות ה-`deny` (בלי `defaultMode`), ואומרים שקלוד ימשיך לשאול לפני כל שמירה.
- **כבר יש `.claude/settings.json`** → לא דורסים. מוסיפים רק את מה שחסר (`defaultMode` אם אין, ואת כל שורות ה-`deny` מהתבנית שחסרות ברשימה הקיימת), ומראים מה נוסף.
- **כבר יש `.gitignore`** → לא דורסים. מוודאים שיש בו שורה `.env`, ומוסיפים אם אין.
- **כבר יש קובץ אחר מהרשימות למעלה** → לא דורסים. כותבים רק את מה שחסר.
- **את הכספת (`.env`) לא יוצרים כאן.** ההגדרות חוסמות את קלוד מלגעת בה, בכוונה. היא נוצרת כשמחברים את הכלי הראשון, ובעל העסק מדביק בה את המפתח בעצמו.
- **כתיבה לתיקייה `.claude` פותחת חלון אישור**, גם אחרי ה"מאשרים". אומרים לפני: "עכשיו ייפתח חלון שמבקש אישור לשמור את קובץ ההגדרות. לוחצים לאשר." נדחה → אומרים מה לא נשמר, ומציעים לנסות שוב.

**בודקים שזה באמת נבנה:** מציגים את רשימת הקבצים בתיקייה (Glob על `**/*` ועל הקבצים שמתחילים בנקודה). צריכים להיות 4 הקבצים הבסיסיים, 4 קבצי הנושא ו-10 השלטים. קוראים שוב את `CLAUDE.md` ואת `memory/MEMORY.md`. משהו חסר או לא נכון → משלימים ובודקים שוב. רק אחרי זה ממשיכים.

## ד. מסבירים את המשרד (פעם אחת, קצר)

מראים את העץ:

```
<שם התיקייה>/
├── CLAUDE.md        ← תעודת הזהות: העסק, המפה והכללים. קלוד קורא אותו בכל שיחה
├── memory/          ← הזיכרון: תוכן עניינים קצר, והפרטים בקבצי נושא
├── systems/         ← איך העסק עובד: מפת העסק, ותיקייה לכל מחלקה
├── projects/        ← תיקייה לכל פרויקט, ובתוכה מה שקלוד מכין
├── team-ai/         ← הצוות הדיגיטלי
├── archive/         ← מה שנסגר
├── .gitignore       ← שומר שהכספת לא תעלה לאינטרנט
└── .claude/
    └── settings.json ← האבטחה

יופיעו בהמשך:
├── .claude/skills/  ← המתכונים                (שלב 4)
├── .claude/agents/  ← קבצי העובדים             (שלב 5)
└── .env             ← הכספת למפתחות          (כשמחברים כלי ראשון)
```

ואחריו ארבע שורות, לא יותר:

- **ככה עובדים:** פותחים תמיד את התיקייה הזו, ואומרים מה רוצים ועל איזה פרויקט. קלוד יודע איפה לשמור כל דבר, כי זה כתוב ב-CLAUDE.md, ובכל תיקייה יש שלט (`README.md`) שאומר מה יש בה.
- **התיקיות מסודרות, והעסק עוד לא בפנים.** כרטיס העסק בתוך תעודת הזהות עוד ריק. ממלאים אותו בשלב הבא.
- **קבצים שמתחילים בנקודה מוסתרים** ב-Finder ובסייר הקבצים. ב-VS Code רואים אותם רגיל. במק מציגים אותם ב-Cmd+Shift+נקודה, בווינדוס בתפריט "תצוגה" ← "פריטים מוסתרים".
- **הכספת עוד לא קיימת, בכוונה.** היא נוצרת כשמחברים את הכלי הראשון, ואתם מדביקים בה את המפתח בעצמכם. קלוד לא נוגע בה.

## ה. סיום

- ההגדרות והזיכרון נטענים רק בשיחה חדשה. נותנים את הודעת "שיחה חדשה" מהיסודות, ומוסיפים: "בשיחה החדשה מקלידים `/office-business`, ונכיר לקלוד את העסק."
- אם בנינו בתיקייה אחרת מזו שהשיחה נפתחה בה (זה לא אמור לקרות) → הודעת "פותחים מחדש" במקום.
